01

准备你需要的东西

一台 Android 手机、一条能传数据的 USB 线，以及 Windows 电脑。大部分手机只需要 Google 官方的 Platform-Tools。

  1. 打开 Google 官方 Platform-Tools 下载页。
  2. 下载 Windows ZIP，解压后打开内层 platform-tools 文件夹。
  3. 确认里面能看到 adb.exe。不要在压缩包预览里直接运行。
  4. 点击资源管理器顶部地址栏，输入 cmd，按回车。黑色命令窗口会直接打开在这个文件夹里。
为什么有些人输入 adb 提示找不到？通常是 CMD 打开在上一层文件夹。你需要进入真正包含 adb.exe 的 platform-tools 目录。
02

打开手机的 USB 调试

以小米澎湃 OS 为例：

  1. 手机进入设置 → 我的设备 → 全部参数与信息，连续点击“OS 版本”约 7 次，开启开发者模式。
  2. 返回设置 → 更多设置 → 开发者选项，开启“USB 调试”。
  3. 用 USB 数据线连接电脑，手机出现“允许 USB 调试”时，确认是你的电脑后选择允许。

其他品牌的菜单不一定一样，可在手机设置里搜索“开发者选项”或“USB 调试”。

不需要做的事无需 Root、无需解锁 Bootloader；也不需要打开“USB 调试（安全设置）”或授予额外的高风险权限，除非手机系统另有明确要求且你理解其影响。

常见问题
为什么 CMD 会提示“adb 不是内部或外部命令”？
你大概率没进入 adb.exe 所在的文件夹。打开真正的 platform-tools 文件夹，在顶部地址栏输入 cmd 回车，再运行 adb devices。
为什么第一次出现 unauthorized，第二次就变成 device？
unauthorized 表示手机尚未授权这台电脑。手机点击“允许 USB 调试”后，再执行一次命令就能变成 device。
为什么不直接删 APK？
系统原始 APK 通常位于只读系统分区。用户级卸载仅改变指定用户的安装登记，更容易验证和恢复，也避免直接修改系统分区。
为什么我的另一台小米不允许禁用或卸载？
Android 版本、厂商改动和包的特权级别都可能影响卸载策略。相同应用名不代表相同包；同一包名也不代表不同构建版本的权限行为一致。
第 06 步的 Java 源码是否来自原作者仓库？
不是逐字复制。此页提供了参考公开技术接口而重新编写的演示源码，固定包名、User 0 和目标系统构建版本，默认只检查接口。该源码已通过 Java 编译，但未独立完成真机验证；真实成功的操作记录来自原作者的方法，详细来源请看下方链接。
安装 VPN 或国外 App 就代表会被监控吗？
不能这么推断。应用权限、网络访问、系统组件与实际的数据上报需要分别证实。卸载一个系统包不能证明其他机制不存在，也不能据此判断某位用户是否受到调查。
网页会自动运行命令吗？
不会。页面完全在浏览器本地运行。复制命令后仍由你自己在电脑 CMD 中确认执行。源码下载也只是下载普通文本文件。
