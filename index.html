SystemHelper Guide

Found an app called SystemHelper on your Android phone? Use Android Debug Bridge (ADB) to check its package name and install state before deciding whether to change anything.

This guide starts with the USB connection and explains what each command does. The page copies commands on request; you decide which ones to run on your computer.

Start with the general checks. Whether Android lets you disable or remove the package depends on the phone and its system build. The advanced method has a recorded success on one specific Xiaomi build.

Check the full package name. The target is com.mobiletools.systemhelper. Leave com.qualcomm.qti.services.systemhelper, a separate Qualcomm system component, alone.

Read the disclaimer before making changes.

Why some users remove SystemHelper

com.mobiletools.systemhelper is preinstalled on some Android phones sold in mainland China. Public analyses link it to China Unicom device management (DM). As a system component, it may be absent from the usual uninstall screen. The reports raise questions about data collection and user awareness. They do not establish that the component is malware.

In November 2026, researchers examining one HyperOS sample and one realme sample reported fields such as these across the versions they examined.

CategoryExamples
DeviceIMEI, device model
SIMIMSI, ICCID, carrier information
Installed appsThird-party app names and package names
App usageForeground usage time and data usage
Network and locationCell tower, signal, or location fields

The reports identified logic for sending data to dm.wo.com.cn:18080. One report analyzed captured traffic on its test device. Code, cached records, and observed traffic provide different kinds of evidence. These findings do not show that every field was received for every phone. Behavior can vary by manufacturer, build, app version, and network.

App lists can reveal more when combined with usage times and device or SIM identifiers. Together, these fields can indicate which apps someone uses and how often. Some owners disable the component or remove it for their user to limit further collection by that component.

Removal is optional. The component may support carrier registration or device management on your phone, and disabling it can affect features. Removing it for one user cannot undo earlier transfers or tell you what other services collect. Check the package, back up important data, and read the risks before deciding.

1. Get ADB ready

Use a Windows computer and a USB cable that supports data. Get Android SDK Platform-Tools from Google and extract the ZIP file.

Open the extracted platform-tools folder and check for adb.exe. Type cmd in File Explorer’s address bar and press Enter. This opens Command Prompt in the right folder.

On macOS or Linux, open a terminal in the extracted platform-tools folder. If adb is missing from your PATH, use ./adb in its place. Select macOS / Linux in step 4 for the matching filters. The advanced example uses Windows CMD.

2. Enable USB debugging

In Settings, open About phone and tap the build or OS version repeatedly to unlock Developer options. Menu names vary. On HyperOS, look under Settings → My device → Detailed info and specs, then Settings → Additional settings → Developer options. Turn on USB debugging.

Connect only the phone you plan to check. Unlock it and approve the USB debugging prompt if you recognize the computer. The recorded Xiaomi procedure used ordinary ADB access with the bootloader locked.

3. Check the connection

Paste this command into the terminal and press Enter.

device means the phone is ready. If you see unauthorized, approve the prompt on the phone and run the command again. If the list is empty, check the cable, USB port, debugging setting, and Windows USB driver. Hide the device serial number before sharing a screenshot.

4. Identify the package and check its state

Several apps can display the name SystemHelper. Match the full package name in the output. If you only see the Qualcomm package or a different name, stop here.

Computer terminal

Confirm the target appears in the system package list before following the removal steps. This procedure covers the preinstalled system package.

Confirm the active user is 0. If you are using a guest profile or a second space, switch back first. In the User 0: line, note installed= and enabled=. Note versionName= for the advanced method. If the target already shows installed=false, skip removal. If any expected line is missing, verify the package and connection.

5. Try standard ADB commands

Continue only if the package name matches, the active user is 0, and the target shows installed=true. Read the recovery steps first. The next two commands change the phone.

If the command returns new state: disabled-user, check for enabled=3. The app can still show installed=true while disabled. If that is enough for you, stop here. Cannot disable system packages. or SecurityException means the system refused the request. Read the current state before trying anything else.

If you still want to remove the package for User 0, use the following command. -k asks Android to keep app data. Back up anything important first.

If you see Success, go to verification. If you see Failure or only root can delete system app for a particular user, check the package state again. If it still shows installed=true, removal did not complete. Any earlier successful disable may still apply.

6. Advanced method for the tested Xiaomi build

Consider this method only for the Xiaomi 17 Pro Max on HyperOS OS4.0.6.0.XPBCNXM with SystemHelper 4.0.0-20260910, after standard removal is refused. If any detail differs, stop after the standard checks.

The upstream test used its own temporary tool to call IPackageManager.deletePackageAsUser as the ordinary ADB shell (UID 2000). The original system APK remained. The separate Java example below passed desktop compilation only. See the upstream record for the exact tested procedure.

Windows example: build, inspect, and submit the request

A. Prepare Java and a work folder

Use JDK 17 or 21. Both tools should print version information. If CMD reports that a command is unrecognized, check the JDK installation and PATH.

B. Save the example source

Open the file in Notepad using the command below. If prompted to create it, choose Yes. Paste the Java source and press Ctrl + S. The file should be named SystemHelperUserTool.java in the systemhelper-tools folder you just created.

View Java source 
import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Method;

/**
 * SystemHelper User Tool — example for a tested Xiaomi 17 Pro Max build.
 * This tool is intentionally fixed to one package, one user and one OS build.
 * It makes a user-scoped package manager request; it does not remove /system APK files.
 * Copyright (c) 2026 HAPPY Games. MIT License.
 */
public final class SystemHelperUserTool {
    private static final String TARGET = "com.mobiletools.systemhelper";
    private static final String TESTED_BUILD = "OS4.0.6.0.XPBCNXM";
    private static final int MAIN_USER = 0;

    public static void main(String[] args) throws Exception {
        String operation = args.length == 1 ? args[0] : "inspect";
        if (!"inspect".equals(operation) && !"confirm-remove".equals(operation)) {
            throw new IllegalArgumentException("Use: inspect or confirm-remove");
        }

        Class<?> process = Class.forName("android.os.Process");
        int callingUid = ((Integer) process.getMethod("myUid").invoke(null)).intValue();
        if (callingUid != 2000) {
            throw new SecurityException("ADB shell UID 2000 required; got " + callingUid);
        }

        Class<?> properties = Class.forName("android.os.SystemProperties");
        String currentBuild = (String) properties.getMethod("get", String.class)
                .invoke(null, "ro.build.version.incremental");
        if (!TESTED_BUILD.equals(currentBuild)) {
            throw new IllegalStateException("Unverified OS build " + currentBuild
                    + " (expected " + TESTED_BUILD + "). Stop here.");
        }

        Class<?> managerInterface = Class.forName("android.content.pm.IPackageManager");
        Object manager = Class.forName("android.app.ActivityThread")
                .getMethod("getPackageManager").invoke(null);
        Class<?> observerType = Class.forName("android.content.pm.IPackageDeleteObserver");
        Method removeForUser = managerInterface.getMethod("deletePackageAsUser",
                String.class, int.class, observerType, int.class, int.class);

        Class<?> constants = Class.forName("android.content.pm.PackageManager");
        int flags = constants.getField("DELETE_KEEP_DATA").getInt(null)
                | constants.getField("DELETE_SYSTEM_APP").getInt(null);

        System.out.println("CHECKED UID=" + callingUid + " OS=" + currentBuild);
        System.out.println("TARGET=" + TARGET + " USER=" + MAIN_USER + " FLAGS=" + flags);
        System.out.println("INTERFACE=" + removeForUser.getName());
        if ("inspect".equals(operation)) {
            System.out.println("READ_ONLY_CHECK_OK");
            return;
        }

        try {
            removeForUser.invoke(manager, TARGET, -1, null, MAIN_USER, flags);
            System.out.println("REQUEST_SENT_CHECK_PACKAGE_STATE");
        } catch (InvocationTargetException error) {
            Throwable cause = error.getCause();
            if (cause != null) cause.printStackTrace();
            else error.printStackTrace();
            System.exit(1);
        }
    }
}

C. Get D8 and check its version

Android runs DEX bytecode. Use D8 from the specified Google R8 build to convert the Java class file. Confirm that D8 prints its version before compiling.

D. Build the temporary tool

Look for classes.dex in the work folder. A JDK 21 warning about source level 8 can appear even when compilation succeeds. If you see error: file not found, check the filename and folder before retrying.

E. Transfer the tool and inspect the interface

Proceed only if the example prints READ_ONLY_CHECK_OK. If you get Permission denied, NoSuchMethodException, or Unverified OS build, stop and remove the temporary file with the cleanup command in step 7.

F. Submit the uninstall request

Run this only after the previous check passes and you still want to remove the package for User 0. Stop if the device, build, package, or output differs from the instructions.

REQUEST_SENT_CHECK_PACKAGE_STATE means the request was submitted. Continue to step 7 to see whether it worked. If the request throws an error, read the current state and clean up the temporary file.

7. Verify, reboot, and check again

For removal, look for installed=false on the User 0: line. For a disable-only change, look for enabled=3. A success message or a missing process is insufficient on its own. Reboot, unlock and reconnect the phone, then check again. Verify mobile data, incoming and outgoing calls, and SMS.

If you transferred the temporary DEX, remove it after verification or when stopping partway through the advanced steps. No output is expected when cleanup succeeds. Turn off USB debugging when finished. Check the package again after a system update or factory reset.

8. Restore the package when needed

User-level removal changes the install state for a specific user. It leaves the original system APK in place. If the APK is still available, try registering it again for User 0.

Check for installed=true. The upstream tests did not attempt recovery on either phone. If you disabled the app earlier, also check enabled=. Restore only the state you recorded before making changes.

If the original value was enabled=0, restore the default state.

If the original value was enabled=1, explicitly enable the package. If the original value differs or a command fails, keep the output and check recovery guidance for your build.

Frequently asked questions

Why can’t Windows find adb?

Open Command Prompt from the folder containing adb.exe. In PowerShell, use .\adb.exe from that folder or switch to CMD.

What does unauthorized mean?

Unlock the phone and approve USB debugging for your computer. If the prompt is missing, revoke USB debugging authorizations in Developer options, reconnect, and run adb devices again.

What if Android refuses disable-user?

Read the package state first. Once you have checked the package, user, and connection, you can try standard user-level removal if you still want it.

What if Android also refuses uninstall --user 0?

Fix connection errors before trying again. If the system explicitly denies removal, stop after the standard checks unless your model and build match the recorded Xiaomi case.

Why is the APK still there after installed=false?

The flag describes whether the package is installed for User 0. The original APK stays in the system partition so Android may be able to register it again with install-existing.

Will this affect calls, SMS, or mobile data?

All three worked in the recorded Xiaomi test. Dependencies can differ between phones and builds. Test these features on your own device after any change.

Do I need root?

Read-only checks and the recorded Xiaomi removal use ordinary ADB shell access. A manufacturer can still block changes made from that account.

Can I use this on another brand?

Use the read-only checks first. Consider standard ADB actions only for the exact target package. The advanced result applies to the model and build in the test record.

Is the bundled Java example the upstream tool?

It is an independent implementation with a fixed package, User 0, and build. It defaults to inspection and passed desktop compilation. The device test used the upstream implementation.

Does the website run any commands?

You run commands yourself in a terminal. The site displays and copies text and stores your language, theme, and step checkmarks in the browser.

Disclaimer and risks

This guide is for technical research and personal device management. Use it only on a device you own or are authorized to manage. You decide whether to make changes and assume the risks of doing so. Compatibility, continued device functionality, and recovery depend on the device and system build.

Back up important data, record the starting state, and check whether your phone relies on the component before making changes. System updates can change both removal and recovery behavior.

Removal checks establish the install state of one package for one Android user. They do not establish what the phone as a whole collects or sends.
